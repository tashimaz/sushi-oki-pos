# สถานะ MVP

| พื้นที่ | สิ่งที่มี |
| --- | --- |
| รับออเดอร์ | 8 โต๊ะ สถานะโต๊ะ เพิ่ม/ลด แก้หมายเหตุ ย้ายโต๊ะ ยกเลิก และ audit trail |
| คิดเงิน | เงินสด เงินทอน ส่วนลดบาทหรือเปอร์เซ็นต์ QR แบบตรวจรับด้วยพนักงาน บันทึกหนึ่งการชำระต่อออเดอร์ |
| เมนู | 11 หมวด ค้นหาไทย เพิ่ม/แก้ไข/นำออกจากเมนู สินค้าหมด หลายขนาด และนำเข้า JSON |
| การพิมพ์ | ใบครัวเฉพาะส่วนที่เปลี่ยน ใบบัญชีแบบเต็มก่อนส่วนลด แจ้งย้ายโต๊ะ คิวถาวร พิมพ์ทดสอบ และ COPY |
| รายงาน | ยอดสุทธิรายวัน ช่องทางชำระ เมนูขายดี ประวัติบิล ประวัติแก้ไข/ยกเลิก และ CSV |
| ข้อมูล | SQLite บน Android, SQLite WASM/IndexedDB บนเว็บ, สำรองและกู้คืน JSON |

## พฤติกรรมที่ควรทราบ

- การเพิ่ม/ลดจำนวนบันทึกทันที หมายเหตุบันทึกเมื่อกดบันทึกหรือย้ายโฟกัสออกจากรายการ และใช้ปุ่มข้อความสำเร็จรูปได้
- ราคาเก็บเป็นสตางค์ และ order item เก็บชื่อกับราคาที่ขายไว้ การนำเมนูหรือขนาดออกยังรักษาข้อมูลสำหรับบิลเดิม
- SQLite schema รุ่น 1 แยกข้อมูลเป็น 11 ตาราง เก็บ record เป็น JSON ในแต่ละแถว พร้อมดัชนีเฉพาะสำหรับโต๊ะที่เปิดและการชำระเงินต่อออเดอร์ Repository ตรวจความสัมพันธ์ก่อนกู้คืน การแก้ไขแต่ละครั้งบันทึกด้วย transaction และเช็ก revision เพื่อกันการเขียนทับพร้อมกัน
- คิดเงินจะเข้าคิวอาหารที่ยังไม่ได้ส่งในธุรกรรมเดียวกับการชำระ ยอดหลังส่วนลดและเงินทอนดูได้ในประวัติบิล
- การกู้คืนเป็นการแทนที่ข้อมูลทั้งชุดตามไฟล์สำรอง งานพิมพ์ค้างในไฟล์จะอยู่ในสถานะผลไม่แน่นอนเพื่อให้ตรวจสอบก่อนพิมพ์ COPY
- MVP ออกแบบสำหรับร้านเดียวและอุปกรณ์เดียว Repository อ่านชุดข้อมูลของร้านเพื่อประมวลผล จึงควรวัดความเร็วอีกครั้งเมื่อมีประวัติขายสะสมปริมาณมาก

## งานตรวจรับที่ยังเหลือ

- ใช้เมนูและราคาจริงจากร้านแทนข้อมูลตัวอย่าง
- ตรวจ vivo Y28 และเครื่องพิมพ์จริงทั้งการจับคู่ ขอบกระดาษ ฟอนต์ไทย กระดาษหมด การตัด Bluetooth ระหว่างส่ง และการกู้คืนหลังไฟดับ
- กำหนดคีย์ลงนาม release และกระบวนการอัปเดตเมื่อพร้อมนำแอปไปใช้ประจำ
